# Transmission Web Manager (TRWM) 像素级重构与深度技术设计方案

## 一、 项目定位与极致重构目标
本方案旨在将 Transmission Web Manager (TRWM) 从陈旧的 jQuery 架构，**像素级（Pixel-Perfect）、零遗漏（Zero-Omission）**地完全重构为基于现代化前端工程体系的超高性能单页应用（SPA）。
重构不仅仅是技术栈的迁移，更是对原项目所有 UI 约束、高密交互、通信握手细节的全面复刻，并在其基础上补齐了对 Transmission 4.1.x+ (JSON-RPC 2.0) 的深度支持（如带宽组、顺序下载等）。项目严格遵从**零外部 CDN 依赖**的离线可用原则。

---

## 二、 UI/UX 规范与布局约束

为了适应高级 NAS 玩家与 PT 爱好者"一屏纵览全局"的极致需求，项目遵循**高信息密度紧凑布局**原则：

### 1. 结构与尺寸标准
* **全局布局**：采用经典三栏结构（顶栏 + 侧边树 + 主表/底部详情分栏）。
* **主任务表格界限**：
  * **行高（Row Height）**：保证高信息密度。
  * **单元格内边距（Cell Padding）**：适当紧凑，确保一屏可容纳较多任务记录。
  * **边框线（Borders）**：使用极细边框，适配深浅模式。
* **底部详情抽屉（Detail Drawer）**：支持拖拽 `resize` 高度，内部 8 个 Tab 标签页采用无边框紧凑排列。

### 2. 色彩系统与状态标示
系统支持深浅两套色彩空间（通过 CSS Custom Properties）：
* **背景与面板**：区分背景、面板和正文的色彩层次。
* **种子的生命周期颜色语义**：
  * **下载中（Downloading）**：蓝色系。
  * **做种中（Seeding）**：绿色系。
  * **暂停/空闲（Stopped）**：灰色系。
  * **错误（Error）**：红色系。
  * **校验中（Checking）**：橙色系，附加进度条动画提示。
  * **排队中（Queued）**：紫色系（如等待下载或做种）。
* **高级半透明融合（Color-mix）**：对于半透明变体，统一采用标准 CSS `color-mix()` 动态计算（例如 `color-mix(in srgb, var(--primary) 10%, transparent)`），拒绝硬编码的 RGBa 乱象。

### 3. 右键菜单与浮层 (Context Menus & Tooltips)
* 弹出式菜单采用现代磨砂玻璃特效，使用 `-webkit-backdrop-filter` 与 `backdrop-filter: blur(...)` 属性实现高雅毛玻璃视觉，具备细微的进入过渡动画。
* 弹出坐标需动态侦测屏幕视口（Viewport）边界，自动向内折叠，杜绝溢出滚动条。

## 三、 现代浏览器前沿特性 (Web APIs) 深度利用

为实现脱离传统库的纯粹性能，我们深度榨取了现代浏览器的底层 API：

1. **HTML5 Canvas 2D API**
   * 用于底部"Pieces（分块）"和"Speed（速度图）"面板的实时渲染。
   * **矩阵图渲染**：根据分块总量动态调整晶格大小和间距，每个晶格叠加高光/阴影形成立体质感。
2. **IndexedDB (经 Dexie 驱动)**
   * 在客户端本地建立高吞吐量的 `twc-database` 库，为**种子历史快照引擎**提供持久化支撑，每秒吞吐百条快照无压力。
3. **HTML5 Drag and Drop API**
   * 全局监听 `dragenter`、`dragover`、`drop`。拦截 `.torrent` 拖拽行为，绕过系统默认打开行为，在页面覆盖 `drop-zone` 遮罩引导用户空投任务。
4. **FileReader API**
   * 使用 `readAsDataURL` 纯在内存中将本地选中的 `.torrent` 文件编码为 Base64 字符串，以拼装 RPC `metainfo` 参数。
5. **IntersectionObserver & ResizeObserver**
   * 配合虚拟滚动引擎，实时侦测列表容器的尺寸变化以及表格行的可见性（Visibility），实现千条数据仅渲染视窗内 40 个 DOM 节点。
6. **CSS Custom Properties (变量) & CSS Grid**
   * 全量摒弃内联样式乱象，建立极其严密的原子级 CSS 变量树（Token Tree）控制全局换肤。
7. **HTML5 Notifications API**
   * 配合定时轮询，监听下载任务的临界状态（`left_until_done` 归零）。在任务完成瞬间调用原生推送通道弹出“任务下载完成”桌面通知，支持后台运行提醒。
8. **Custom Protocol Handler API**
   * 深度整合系统级行为，通过 `navigator.registerProtocolHandler` 将应用注册为操作系统的 `magnet:` 默认下载器。点击任意网页的磁力链接，自动唤起 WebUI 并解析 `?uri=` 进行一键下载。
9. **TextDecoder API (二进制 MaxMind MMDB 数据流解码)**
   * 在纯前端 GeoIP 解析中，深度利用 `TextDecoder('utf-8')` 来高速解算 MMDB 二进制树节点中的变长字节数据段，直接还原为标准 JS 字符串，确保毫秒级的超高性能查表。
10. **AbortSignal.timeout (网络高并发主动超时控制)**
    * 在本地 Tracker 测速中心，通过向并发 `fetch` 请求注入 `AbortSignal.timeout(5000)`，实现对连通异常 Tracker 的秒级超时阻断，保障列表总体轮询的灵敏度。
11. **requestAnimationFrame (硬件级平滑动画重绘)**
    * 全局大盘速度图表与单任务速度图表通过 `requestAnimationFrame` 挂载绘制循环。在每帧绘制时侦测容器物理尺寸，实现视网膜屏高 DPI 像素重算与平滑动态重绘，达到完美的 60FPS 运动平滑度。

## 五、 全站功能菜单与交互组件深度拆解

必须 100% 复刻以下所有菜单与交互链路：

### 1. 顶部主控台 (Top Toolbar)
* **状态总览**：Transmission RPC 连通状态绿点标识。
* **高频操作按钮群**：
  * `Add` (添加)：唤起全功能添加对话框。
  * `Start` / `Pause`：对选中项生效。
  * `Delete`：弹出二次确认，内含 `[ ] 永久删除本地文件数据` 危险项复选框。
  * `Alt-Speed` (备用限速小乌龟)：点击即时触发布局联动并发送 `session-set`。
* **搜索与视图**：全局 Search 模糊匹配（响应式过滤表格，输入框获取焦点时具有平滑的宽度延展动画），强制 Refresh 按钮。
* **快速设置 (QuickSettings)**：集成“关联磁力链接”、“下载完成桌面通知”等本地功能开关，以及高频的网络/速度偏好切换快捷键。

### 2. 左侧过滤导航树 (Filter Side-Tree)
* **状态过滤面板**：展示全部、下载中、做种中、暂停、异常、校验中的分类计数器。
* **动态聚合标签组**：
  * `Directories`：自动根据现有任务的路径聚合成树状分类。
  * `Labels`：读取所有任务的标签进行聚合。
  * `Trackers`：根据 Tracker 域名对任务归类。

### 3. 高密度虚拟任务表格 (Virtual Torrent Table)
* **10大核心数据列**：名称、状态徽章、大小、带文本与百分比的动态进度条、下载速率、上传速率、剩余时间 (ETA)、排队顺位、已完成量、添加时间。
* **交互规则**：支持按住 Shift 连续多选、Ctrl 点选；支持点击表头边缘的把手（Handle）进行自由拖拽改动列宽；支持表头右键显示菜单开启/隐藏指定列。

### 4. 底部八大详细分析面板 (Detail Tabs)
1. **常规 (General)**：呈现 40+ 明细键值对（Hash, Creator, Pieces count, MIME, Verified bytes 等）。
2. **文件 (Files)**：
   * 用树形或扁平表单展示种子包含文件。
   * 支持复选框改变文件下载意愿（`wanted`/`unwanted`）。
   * 支持循环点击修改优先级（High, Normal, Low）。
   * **[特色增强]**：每一行携带编辑铅笔图标，支持行内（Inline Rename）触发 `torrent-rename-path`。
3. **服务器 (Trackers)**：包含每一层 Tier 的 URL；双击或点击 `[ i ]` 显示其 Announce / Scrape 的响应耗时、状态码及最新节点返回量；支持右键批量替换。
4. **用户 (Peers)**：
   * **GeoIP 集成**：本地高精度二进制 MMDB 库高速解析 IP 映射为国家代码，动态通过 ISO emoji 转换或 SVG 国旗库进行国旗图标与国家名国际化渲染。
   * **极客属性列**：展示 uTP/TCP 协议，入站与出站速度，Peer 下载进度，以及微型客户端标识（如 `uTorrent 3.5.5`）。
   * **复杂 Flags 字典**：详细展现并图解连接状态（如 `D` 正在下载, `U` 正在上传, `H` 经 DHT 发现, `E` 已加密等）。
5. **分块 (Pieces)**：
   * **分块矩阵图谱**：根据 piece 总数动态伸缩晶格大小 (5px/6px/8px)，并在 Canvas 2D 中完成高速铺贴。
   * **动态 Availability（可用度）色偏图谱**：除了呈现已下载（蓝色）与未下载（深灰）方格，还深度融合对等端可用性数据。若分块未下载，则根据拥有该片段的 peer 数量动态演变颜色：
     * **红色 (av = 0)**：无 Peer 拥有（死种危险，极度直观）。
     * **橙色/黄色/绿/浅绿**：根据 Peer 覆盖份数递增演变，提供极为生动的健康度监控。
   * **[特色增强] 起点劫持重设**：支持点击 Canvas 任意 Piece 晶格，计算位置索引并弹出 contextMenu。允许用户一键配置 `sequential_download_from_piece`（连续下载起点），对视频文件“边下边播”的缓冲机制具有决定性优化。
6. **Web 种子 (Webseeds)**：呈现当前任务所对接的所有 HTTP/FTP 外部网络种源，动态展示活动中 Webseed 的实时接收速率 (`webseeds_sending_to_us`)。
7. **速度图表 (Speed)**：通过原生 Canvas 硬件级绘制近 30 次轮询周期的双线重叠渐变面积图，支持下载蓝与上传绿的双曲线重叠面积渐变渲染，并能够根据最大速度智能换算网格 Y 轴上限单位（KB/s, MB/s）。
8. **设置 (Settings)**：对单个种子的控制台，包括设置限速阀值、带宽组 (Group)、单任务连接并发上限、自动停止做种的分享率比例。

### 5. 全局系统配置总控中心 (12 个完整配置页签)
该模态框涵盖了传输守护进程（Transmission Daemon）的所有能力，对应 `session-set` 请求：
1. **Download (下载)**：默认目录、临时 (Incomplete) 目录开关与路径、未完成后缀追加、自动开始开关。
2. **Speed (速度)**：全局带宽限制，以及**带星期时间掩码 (Daymask) 的计划任务限速**设置。
3. **Groups (带宽限制组)**：Transmission 4.0+ 核心特性。管理所有限速分组，决定分组是否遵循全局限速。
4. **Network (网络)**：监听端口开关、启动随机端口、UPnP/NAT-PMP 穿透开关、加密偏好 (Tolerated/Preferred/Required)、防暴破开关 (Brute Force)、uTP/TCP 偏好优先级。
5. **Peer (节点)**：全局节点数封顶值配置。
6. **Seeding (做种)**：全局分享率及闲置时间停种配置。
7. **Queue (队列)**：排队最大并行数与停滞判断（Stall）阀值设置。
8. **Labels (标签)**：管理系统的本地持久化预设标签库池。
9. **Blocklist (黑名单)**：黑名单开关及 URL，一键“强制更新黑名单”，以及极其重要的 **一键测试端口可达性按钮**（可选择 IPv4 或 IPv6 进行试探）。
10. **RPC (连接信息)**：系统只读属性（RPC 版本、API 最低兼容要求）。
11. **Script (自动化脚本)**：支持指定系统后台脚本的绝对路径，用于各种生命周期钩子回调。
12. **Advanced (高级)**：设置磁盘缓存（Cache Size MiB），维护**默认 Tracker 注入列表**。

### 6. 独立模块：本地高级 Tracker 聚合与时延测速中心 (Tracker Aggregator & Speed Tester)
* **动态聚合器**：整合了 ngosang、XIU2 等知名的“最佳/全量”公共列表 CDN，支持用户实时配置、开关或增加自定义订阅源，并提供手动输入面板。
* **标准化去重**：对所有输入源执行域名低劣化、尾斜杠修剪、无效协议检测过滤。
* **高并发无侵入式测速**：在浏览器沙箱中，发起并发的 `no-cors` HEAD 探测请求，挂载 `AbortSignal.timeout` 拦截，秒级抓取各个 Tracker 的 HTTP 响应延时并从低到高排列。
* **多层级策略生成**：支持“Mixed（交错协议混合）”和“Protocol（按协议独立建组）”的 Tier 智能重组算法，规避单一网络制式崩溃导致的 Tracker 整体失效。
* **双向应用网关**：可一键将优化后的去重 Tier 组应用至 Transmission 全局默认配置 (`session_set`)，或批量注入当前选中的活跃 Torrent。

### 7. 独立模块：本地智能历史档案馆 (History Module)
* **运行态快照与 EMA 测速技术**：为克服旧有 WebUI 在任务被删除或下载完毕瞬间，传输速度统计突然断流归零、失去历史轨迹的缺陷。TRWM 在 2 秒间隔的轮询中为所有下载中任务维护时间切片。特别地，对于下载/上传速率，采用**指数移动平均 (EMA) 算法**：
  $$\text{EMA}_{\text{new}} = \text{EMA}_{\text{prev}} \times 0.8 + \text{Rate}_{\text{current}} \times 0.2$$
  在此基础上求出任务在真实下载周期中的平均速度并持久化归档至 IndexedDB (Dexie)。
* **导出与挽回**：当种子被删除后，可在历史列表中找回其磁力链接、分块大小、最终分享率、首尾时间戳，以及内部文件树快照。支持一键导出包含高精度统计的 JSON 与 CSV 文件。

### 8. 独立模块：零依赖超轻量级 i18n 翻译引擎 (Zero-Dependency i18n Engine)
* **原子化设计**：完全舍弃外部多语言库包，在 `src/utils/i18n` 中手写高能翻译器。
* **路径解构与级联 Fallback**：支持扁平与深度嵌套的 JSON 树状 Key 寻址（如 `tracker_agg.stat_final`）。
* **动态参数内含**：翻译串中支持 `{param}` 占位符的自动插值替换（支持数字、字符）。当当前选中的本地语言 (如 `zh-CN`) 存在翻译键值缺失时，系统自动级联检索英文词典进行容错回退，杜绝界面出现空白或乱码。

### 9. 独立模块：高性能自适应拖拽列宽系统 (Resizable Columns Hook)
* **流式坐标解算**：使用自定义 Hook `createResizableColumns`，对表格与历史列表的列宽变化进行细粒度追踪。完美兼容移动端 Touch 事件与桌面端 Mouse 事件。
* **帧速护卫 (RAF) 与非阻塞持久化**：在列宽拖拽改变的过程中，列宽像素状态由 `requestAnimationFrame` 约束更新，在微秒级帧周期中完成真实 DOM 的局部尺寸伸缩。为了规避频繁写入 `localStorage` 造成的渲染主线程阻塞，列宽数据仅在拖动完全结束（`mouseup`/`touchend`）的一瞬间执行持久化同步。

## 六、 接口协议与核心字段全量字典 (Transmission JSON-RPC 2.0)

本项目以 Transmission 4.1.x (RPC semver 6.0.0+) 的 **JSON-RPC 2.0 协议**为主要通信协议，同时适当兼容旧版本（3.x/4.0.x）的旧式 RPC 协议。兼容层代码独立存放在 `src/api/rpc-legacy.ts` 中。

### 1. JSON-RPC 2.0 协议要点

Transmission 4.1.0 起正式支持 JSON-RPC 2.0 规范，并将所有 RPC 字符串统一为 **snake_case**。旧的混合格式（kebab-case / camelCase）仍被支持但已标记为弃用（deprecated），将在未来版本中移除。

**请求格式（JSON-RPC 2.0）：**
```json
{
  "jsonrpc": "2.0",
  "method": "torrent_get",
  "params": {
    "fields": ["id", "name", "hash_string", "status"],
    "format": "table"
  },
  "id": 1
}
```

**响应格式（JSON-RPC 2.0）：**
```json
{
  "jsonrpc": "2.0",
  "result": {
    "torrents": [...]
  },
  "id": 1
}
```

**关键差异（新协议 vs 旧协议）：**

| 维度 | JSON-RPC 2.0 (4.1.0+) | 旧式协议 (3.x/4.0.x) |
|:---|:---|:---|
| 请求必须包含 | `"jsonrpc": "2.0"` | 无此字段 |
| 参数键名 | `"params"` | `"arguments"` |
| 响应数据键名 | `"result"` | `"arguments"` |
| 方法名格式 | `torrent_get` (下划线) | `torrent-get` (连字符) |
| 字段名格式 | `hash_string` (snake_case) | `hashString` (camelCase) / `hash-string` (kebab-case) 混合 |
| 错误格式 | `json.error.message` + `json.error.data` | `json.result = "error message"` |
| Session ID | 仍通过 HTTP 409 + `X-Transmission-Session-Id` 头获取 | 同左 |

### 2. Table Format 高效数据传输

`torrent_get` 方法支持 `"format": "table"` 参数，相比默认的 `"format": "objects"` 格式，table 格式在 JSON 生成和解析方面都更高效：

**objects 格式（默认，旧版）：**
```json
{
  "torrents": [
    {"id": 1, "name": "archlinux.iso", "status": 4},
    {"id": 2, "name": "ubuntu.iso", "status": 6}
  ]
}
```

**table 格式（推荐）：**
```json
{
  "torrents": [
    ["id", "name", "status"],
    [1, "archlinux.iso", 4],
    [2, "ubuntu.iso", 6]
  ]
}
```

table 格式的第一行为字段名数组（header），后续每行为一条种子的值数组。当种子数量较多时，table 格式可显著减少 JSON 体积和解析时间。

本项目在 `rpc.ts` 的 `torrentGet()` 函数中自动处理 table 格式解析，将其转换为对象数组供上层使用。

### 3. 旧版本兼容策略

兼容层代码独立存放在 `src/api/rpc-legacy.ts`，负责：

1. **协议自动检测**：首次请求时发送 JSON-RPC 2.0 格式，若响应不包含 `jsonrpc` 字段则回退到旧式协议
2. **字段名映射**：将旧版的 kebab-case/camelCase 响应字段统一转换为 snake_case

5. **响应键名适配**：自动从 `arguments` 读取响应数据（而非 `result`）

### 4. 架构优化决策

#### 4.1 前端差异化更新（后端全量拉取）

**决策**：后端保持每 2 秒全量拉取所有种子数据（不使用 `recently-active`），前端通过逐条 `reconcile` 实现差异化 UI 更新。

**原因**：
- `recently-active` 在 JSON-RPC 2.0 + table format 下不可靠：不活跃种子的 `upload_ratio` 更新可能丢失、`removed` 字段可能缺失、新增但未开始下载的种子可能不在列表中
- 后端全量拉取保证数据一致性，前端逐条 reconcile 保证只有变化的种子字段触发 UI 重渲染

**实现** ([torrentStore.ts](file:///home/qq/code/trwm/src/store/torrentStore.ts))：
```typescript
// 首次初始化：整体 reconcile
setTorrentStore('items', reconcile(newItems));

// 后续更新：逐条 reconcile（只更新变化的种子）
for (const t of data.torrents) {
  setTorrentStore('items', t.id, reconcile(t as Torrent));
}
// 删除已移除的种子
setTorrentStore('items', id, undefined);
```

#### 4.2 移除 `void t.xxx` hack

**旧做法**：在 `torrentList` Memo 中遍历所有种子访问 `rate_download`、`status` 等属性来"预热"依赖追踪。
**新做法**：逐条 `reconcile` 后 SolidJS Store 的细粒度响应式自动追踪字段访问，无需手动 hack。

### 9. 关键注意事项清单（开发者必读）

1. **RPC 调用必须用 snake_case** — 写任何新的 `rpcCall` 时，方法名 and 参数名必须是下划线格式
2. **SolidJS Store Proxy 不能序列化** — 存入 IndexedDB 前必须 `JSON.parse(JSON.stringify())`
3. **`reconcile` 用于深度比较** — 整体替换时用；`produce` 用于 targeted mutations（本项目最终选择逐条 reconcile 方案）
4. **`on()` 控制依赖** — `createEffect(on(selectedIds, callback))` 确保副作用只在特定信号变化时执行
5. **lazy() 需要 default export** — named export 需用 `.then(m => ({ default: m.Xxx }))` 包装
6. **lucide-solid 组件接受 SVG 属性** — 但 TypeScript 类型定义可能不含 `class`，需在接口中显式声明 `class?: string`
7. **虚拟滚动 count 必须是 getter 函数** — `<For each={list()} />` 或 `<Virtualizer count={() => list().length} />`
8. **Session ID 通过 HTTP 409 获取** — 首次请求会收到 409 状态码，需从响应头 `X-Transmission-Session-Id` 取出并在后续请求中带回
9. **不要使用 `recently-active` 做增量更新** — 在 JSON-RPC 2.0 + table format 下行为不可预测
10. **GlobalConfigModal 的 session-set 调用** — 所有参数必须是 snake_case，与 Session 接口字段名一一对应
