# Transmission 配置项前端实现分析报告

基于 Transmission 4.1.1 (RPC 19 / semver 6.0.1) 的 `settings.json` 配置文件，与本项目前端设置对话框的已实现配置项进行逐项对比，分析未实现配置项的 RPC 可写性和前端实现必要性。

---

## 一、数据来源

| 来源 | 说明 |
|------|------|
| `settings.json` | Transmission 守护进程的完整配置文件，共 62 个配置项 |
| `session-get` RPC | 通过 RPC 可读取的会话字段，共 48 个字段 |
| `session-set` RPC | 通过 RPC 可写入的会话字段（经本地实例逐一测试验证） |
| `config.js` CONFIG_ITEMS | 本项目前端设置对话框已实现的配置项，共 39 个（含 4 个只读） |

## 三、未实现配置项详细分析

### A. RPC 可写且建议实现（高优先级）

这些配置项可通过 `session-set` 修改，且对用户有实际价值。

#### 1. `announce-ip` / `announce-ip-enabled`

| 属性 | 值 |
|------|-----|
| 类型 | string / boolean |
| 默认值 | `""` / `false` |
| 官方说明 | 向 Tracker 宣告的替代 IP 地址；启用后使用该值代替客户端真实地址 |
| RPC 可写 | ✅ 已验证 |
| session-get 可读 | ✅ |
| 建议实现 | ⭐⭐⭐ 强烈建议 |
| 前端类型 | toggle + text |
| 建议位置 | 网络 → IP 宣告 |
| 理由 | 对于 NAT 穿透或需要指定宣告 IP 的场景非常重要，官方 GUI 已实现 |

#### 2. `peer-port-random-low` / `peer-port-random-high`

| 属性 | 值 |
|------|-----|
| 类型 | number / number |
| 默认值 | `49152` / `65535` |

| RPC 可写 | ✅ 已验证 |

| 建议实现 | ⭐⭐⭐ 强烈建议 |
| 前端类型 | number（依赖 `peer-port-random-on-start`） |
| 建议位置 | 网络 → 端口设置 |
| 理由 | 已实现 `peer-port-random-on-start` 开关，缺少范围配置不完整；用户可能需要限制端口范围以适配防火墙规则 |

### 关于 RPC 类配置项的特别说明

`rpc-*` 系列配置项（认证、白名单、端口、绑定地址等）虽然全部可通过 `session-set` 修改，但**强烈建议不在前端实现修改功能**。原因：

1. **自锁风险**：修改 RPC 认证、白名单、端口等配置后，当前 Web 会话会立即断开
2. **无法回滚**：会话断开后无法通过 Web 界面恢复，只能手动编辑配置文件
3. **官方做法**：Transmission 官方 Web 客户端也不提供这些配置的修改界面
4. **安全考虑**：通过 Web 界面暴露 RPC 安全配置存在被恶意修改的风险

如需展示 RPC 配置信息，建议仅以只读方式在 RPC 标签页中展示（已实现 `rpc-version`、`rpc-version-semver`、`rpc-version-minimum`、`session-id`），可考虑增加以下只读字段：

- `rpc-port`（当前 RPC 端口）
- `rpc-authentication-required`（是否启用认证）
- `rpc-whitelist-enabled`（是否启用白名单）
- `rpc-host-whitelist-enabled`（是否启用主机名白名单）

### 关于 session-get 不可读字段的说明

部分配置项（如 `peer-port-random-low/high`、`preallocation`、`umask`、`watch-dir` 等）不在 `session-get` 返回值中，但可通过 `session-set` 写入。实现前端 UI 时需注意：

1. 页面加载时无法获取当前值，只能使用默认值或空值
2. 保存时需明确告知用户"当前值未知，将覆盖为输入值"
3. 可考虑在保存前先通过 `session-set` 读取验证（但 Transmission 不支持此方式）
4. 最佳实践：首次加载时标记为"未读取"，用户修改后才提交该字段
